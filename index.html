📊 1. Prefix Sums (1D & 2D)

A prefix sum array transforms queries about the sum of contiguous subarrays into constant time $O(1)$ operations after an initial $O(N)$ preprocessing pass.

#include <vector> // Precomputing 1D Prefix Sums (1-indexed) std::vector<long long> pref(n + 1, 0); for (int i = 1; i <= n; ++i) { pref[i] = pref[i - 1] + a[i]; } // Query sum in range [L, R] in O(1): long long range_sum = pref[R] - pref[L - 1];

2D Grid Prefix Formula:
pref[r][c] = grid[r][c] + pref[r-1][c] + pref[r][c-1] - pref[r-1][c-1]
Sub-rectangle sum $(r_1, c_1)$ to $(r_2, c_2)$:
sum = pref[r2][c2] - pref[r1-1][c2] - pref[r2][c1-1] + pref[r1-1][c1-1]

⚡ 2. Difference Array (Range Updates)

When given multiple queries to add value $x$ to every element in index range $[L..R]$, doing so naively is $O(Q \times N)$. With a difference array, each update is $O(1)$, and the final array is reconstructed with one prefix sum pass in $O(N)$.

// Add 'val' to all elements in range [L, R] (1-indexed) diff[L] += val; diff[R + 1] -= val; // Reconstruct final array: for (int i = 1; i <= n; ++i) { diff[i] += diff[i - 1]; arr[i] += diff[i]; }

🧩 3. Constructive Algorithms & Invariants

Constructive problems do not ask for a single number; they ask you to construct a sequence, grid, or graph satisfying given properties. Key strategies:

  • Analyze Small Cases ($N=1, 2, 3, 4$): Write down all valid outputs by hand to find recurring patterns.
  • Parity Invariants: Check sum of elements, count of odd vs even numbers, and invertibility under XOR.
  • Extremal Principle: Look at minimum or maximum values ($1$, $N$, or infinity) and place them first.

🪙 4. Greedy Techniques

A greedy algorithm works only when a locally optimal choice is guaranteed to lead to a globally optimal solution. Always prove greedy choice via the Exchange Argument:

// Interval Scheduling: sort by earliest finish time std::sort(intervals.begin(), intervals.end(), [](const auto& a, const auto& b) { return a.end_time < b.end_time; });

📐 5. Number Theory & Modular Arithmetic

Competitive programming frequently requires computation modulo $10^9 + 7$ or $998244353$. Division under modulo requires the modular multiplicative inverse using Fermat's Little Theorem ($a^{P-2} \equiv a^{-1} \pmod P$ when $P$ is prime).

long long power(long long base, long long exp) { long long res = 1; base %= MOD; while (exp > 0) { if (exp & 1) res = (res * base) % MOD; base = (base * base) % MOD; exp >>= 1; } return res; } long long modInverse(long long n) { return power(n, MOD - 2); }
